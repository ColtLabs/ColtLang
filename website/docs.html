ColtLang Documentation

Colt is a declarative, multi-paradigm query and data language. It provides a single, high-performance compiler, execution runtime, and CLI for coordinating relational tables, nested documents, key-value stores, vector embeddings, and graph structures.

Introduction

Modern applications frequently interact with heterogeneous database engines: PostgreSQL for relational tables, MongoDB for document payloads, Redis for caching, Pinecone/Milvus for vector search, and Neo4j for graph relationships.

ColtLang replaces brittle, multi-driver glue code with a clean, strongly-validated declarative language. A .colt program specifies:

  • Connections: Authenticated data endpoints with aliases and credentials loaded safely from environment variables.
  • Collections: Typed schema structures and data abstractions across heterogeneous engines.
  • Operations: Declarative reads (FIND), writes (PUT, CREATE), deletions (DELETE), and atomic blocks (ATOMIC).
Declarative, Not Imperative
Colt is not a general-purpose programming language. It contains no unbounded loops, arbitrary memory allocations, or unsafe I/O. Every .colt file is parsed, checked against backend capabilities, compiled into an execution plan (CPA), and orchestrated predictably.

Installation & Verification

Colt distributes native, precompiled binaries for Windows (x86_64), macOS (Apple Silicon & Intel), and Linux (x86_64). You do not need to install Rust or Node.js to use Colt.

One-Command Installation

Run the platform installer from your terminal:

Windows PowerShell:
irm https://coltlang.dev/install.ps1 | iex
macOS / Linux:
curl -fsSL https://coltlang.dev/install.sh | sh

Verify Installation

Check that the binary is available in your PATH:

$ colt --version
colt 0.2.0

$ colt doctor
[COLT DOCTOR] Toolchain & Environment Diagnostics
  CLI Version:       colt 0.2.0 (Rust native)
  Working Directory: E:\Projects\ColtLang
  Database Engine:   COLTANE_URI configured (http://localhost:8080)
  Backend Status:    Available and healthy
  All systems operational.

Your First .colt File

Create a file named library.colt in your project directory:

library.colt 
connection main "postgres://localhost:5432/app"

collection Books {
  id: string,
  title: string,
  author: string,
  year: int,
  available: bool
}

FIND Books WHERE available == true
PUT Books {
  id: "b-101",
  title: "Distributed Systems Design",
  author: "B. Stone",
  year: 2024,
  available: true
}

Previewing with Dry-Run

Before executing any mutations against a live database, validate the operations with --dry-run:

$ colt run library.colt --dry-run
======================================================================
  COLT EXECUTION PREVIEW (DRY-RUN)
  File: library.colt
  Mode: Validation and capability simulation only (Zero mutations)
======================================================================
[PREVIEW] Validated 2 operations across 1 collection:
  [1] FIND Books (Filter: available == true) -> Read operation
  [2] PUT Books (Payload: 5 fields) -> Mutation operation
[SUCCESS] Dry-run complete. 0 operations executed. Source is valid.

Connections & Aliases

Connections define upstream storage targets. You can specify a direct URI or reference an environment variable for safe credential management: 

// Named connection aliases
connection primary "postgres://user:pass@localhost:5432/primary_db"
connection docStore "mongodb://localhost:27017/analytics"
connection cache "redis://localhost:6379/0"

// Using environment variables (recommended)
connection secureVault env("DATABASE_URL")
Credential Redaction Guarantee
The Colt CLI and runtime automatically sanitize sensitive URIs in terminal logs, JSON reports, and error messages. Passwords and API tokens are never leaked to stdout.

Collections & Schemas

Collections map to tables, collections, buckets, or indices depending on the target backend: 

collection Users {
  id: string,
  email: string,
  role: string,
  metadata: object,
  tags: [string]
}

Supported primitive field types include:

  • string: UTF-8 character string
  • int: 64-bit signed integer
  • float: 64-bit IEEE 754 floating point
  • bool: Boolean (true / false)
  • object: Nested JSON key-value document
  • [T]: Array of homogeneous or structured elements

Queries (FIND)

The FIND statement reads records from a collection:

// Simple query
FIND Users

// Filtered query with comparison operators
FIND Users WHERE role == "admin" && age >= 21

// Projection and sorting
FIND Users SELECT id, email WHERE active == true ORDER BY email ASC LIMIT 50

Mutations (PUT, CREATE, DELETE)

Colt provides explicit declarative statements for data modification:

// PUT: Inserts or updates (upserts) by primary key
PUT Users {
  id: "u-99",
  email: "alex@example.com",
  role: "engineer"
}

// CREATE: Explicit insert with unique constraint validation
CREATE Users {
  id: "u-100",
  email: "sarah@example.com",
  role: "lead"
}

// DELETE: Removes matching records
DELETE Users WHERE id == "u-99"

Atomic Transactions (ATOMIC)

Wrap multi-statement writes in an ATOMIC block when the target backend supports transactional guarantees: 

ATOMIC {
  PUT Accounts { id: "acc-1", balance: balance - 100 }
  PUT Accounts { id: "acc-2", balance: balance + 100 }
  CREATE AuditLog { event: "transfer", amount: 100, timestamp: 1714000000 }
}

Relational Data Handling

Relational results are rendered as structured ASCII tables with aligned columns, headers, and record counts. 

+-------+-----------------------------+-----------+--------+
| id    | title                       | author    | year   |
+-------+-----------------------------+-----------+--------+
| b-101 | Distributed Systems Design  | B. Stone  | 2024   |
| b-102 | Database Internals          | A. Petrov | 2019   |
+-------+-----------------------------+-----------+--------+
2 records returned (14ms)

Document Stores

For MongoDB and document backends, nested properties, embedded lists, and dynamic objects are preserved in syntax-highlighted tree format.

Key-Value Stores

Fast key-value operations (Redis, Memcached) display TTL, key presence, mutation status, and structured key inspection cards.

Vector Embeddings

Similarity search outputs show nearest neighbors ranked by cosine similarity or euclidean distance, preserving actual match scores: 

+------+-----------------------------+------------+
| Rank | Document Chunk              | Similarity |
+------+-----------------------------+------------+
| 1    | "Colt compiler parses AST"  | 0.9421     |
| 2    | "Query planning with CPA"   | 0.8875     |
+------+-----------------------------+------------+

Graph Traversals

Graph queries render node-edge-node traversals, hop distances, and relationship properties cleanly.

Executing with colt run

The colt run command processes source through the complete compiler and execution pipeline:

  1. Parse: Validates lexical tokens and grammar against the Colt language specification.
  2. Semantic Check: Verifies field types, connection targets, and operation constraints.
  3. Capability Check: Ensures requested operations are supported by target storage adapters.
  4. Plan Generation: Assembles a Colt Plan Assembly (CPA).
  5. Execution Orchestration: Dispatches statements to ColtaneDB (POST /api/v1/query) or verified native adapters.
  6. Presentation: Renders paradigm-specific outputs or machine-readable JSON.
No Fake Execution Fallback
If ColtaneDB or the required storage engine is unreachable, colt run terminates with exit code 2 and an actionable diagnostic message. It never silently downgrades to plan-only mode or fabricates successful execution.

Dry-Run Mode (--dry-run)

Run any .colt file with --dry-run to simulate execution without executing any database mutations. Dry-run performs full lexical analysis, parsing, semantic verification, and planning, then outputs a preview of what would be executed.

Output Modes (--json, --verbose, --quiet)

Colt supports scriptable and pipeline-friendly output options:

  • --json: Outputs pure JSON to stdout. Spinners, banners, and ANSI color codes are stripped automatically.
  • --verbose: Prints per-statement execution times, memory buffers, and engine metadata.
  • --quiet: Suppresses decorative headers and banner text.

Exit Codes

Exit Code Status Meaning
0 SUCCESS Command executed successfully, or validation passed with zero errors.
1 COMPILATION_ERROR Lexical, syntax, or semantic validation failed. Source is invalid.
2 RUNTIME_ERROR Database engine unreachable, execution timeout, or transaction failure.

Interactive Terminal UI (TUI)

Running colt without arguments in an interactive terminal opens the full-screen terminal workspace.

Built natively in Rust using ANSI virtual terminal processing, the Colt TUI features a distinctive copper-accented aesthetic inspired by modern AI developer tools.

In-TUI Commands

Inside the interactive session, use slash commands to inspect and run code:

  • /run <file.colt>: Execute a source file interactively.
  • /check <file.colt>: Validate syntax and semantics.
  • /plan <file.colt>: Generate and display execution plan.
  • /doctor: Run comprehensive toolchain diagnostics.
  • /capabilities: View supported paradigm matrix.
  • /theme [dark|copper|light|mono]: Switch terminal color palette.
  • /history: View previously executed commands.
  • /clear: Reset the terminal output buffer.
  • /help: Display in-terminal command cheat sheet.
  • /exit (or Ctrl+C / Ctrl+D): Exit workspace.

Themes & NO_COLOR Standard

Colt strictly honors the NO_COLOR specification. When the NO_COLOR environment variable is set or TERM=dumb is detected, all ANSI color codes and styles are omitted.

colt doctor

colt doctor is a non-destructive read-only diagnostic utility that audits:

  • Native CLI version and build target
  • Current working directory and active .colt files
  • Environment configuration (with redacted credentials)
  • ColtaneDB execution engine connectivity (http://localhost:8080/health)

Compiler Diagnostic Codes

Colt uses stable, structured diagnostic codes across compiler, CLI, and language server:

Code Category Description
COLT1001 Syntax Unexpected token or missing punctuation.
COLT1002 Syntax Unclosed string literal or invalid escape sequence.
COLT1005 Syntax Missing collection identifier or empty body.
COLT2001 Semantic Undefined collection referenced in query or mutation.
COLT2004 Semantic Type mismatch in field assignment or comparison.
COLT2012 Capability Requested operation (e.g., vector search) unsupported by target backend.
COLT2027 Semantic Invalid atomic block boundary or uncommitted nested transaction.
