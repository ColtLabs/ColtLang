Hosting & Domain Migration Runbook

ColtLang strictly separates brand identity, documentation hosting, and native binary releases. This guide outlines how to migrate between static web hosting providers (such as Vercel and Cloudflare Pages) or switch to a new canonical domain without breaking existing user installations.

Core Architectural Principles

Principle 1

Hosting Never Hosts Native Binaries

The website serves static documentation, landing pages, and short installation endpoint scripts (/install.ps1, /install.cmd, /install.sh). Native colt executable artifacts are published to and downloaded from verified GitHub Releases with SHA-256 checksum manifests.

Principle 2

Centralized Canonical Configuration

The public URL is configured in a single file: website/site.config.js via PUBLIC_SITE_URL. All canonical tags, Open Graph headers, and installation copy commands are dynamically generated from this single source of truth. No domain strings are hardcoded in application logic.

Principle 3

Deterministic Static Build

The website requires no database, authentication system, or Node.js server. The build process (npm run build) outputs pure static HTML, CSS, JavaScript, and installer scripts into website/dist/.

Migrating Between Vercel and Cloudflare Pages

Because the same custom domain (e.g. https://coltlang.dev) is retained, user installation commands never change during a hosting provider switch.

Step 1

Build and Verify the Static Site Locally

Run the independent website build and test suite:

cd website
npm run build
npm test

Verify that dist/ contains index.html, install.html, docs.html, migration.html, install.ps1, install.cmd, and install.sh.

Step 2

Deploy to Cloudflare Pages (Parallel Staging)

  1. Link the GitHub repository in the Cloudflare Pages dashboard.
  2. Configure Build Settings:
    • Build command: npm run build
    • Build output directory: dist
    • Root directory: website
  3. Set Environment Variable: PUBLIC_SITE_URL=https://coltlang.dev.
  4. Trigger deployment. Cloudflare Pages assigns a staging URL (e.g. coltlang.pages.dev).
Step 3

Verify Endpoints on Staging Deployment

Test the installation endpoints before modifying any DNS records:

# Verify HTTP status 200 and Content-Type: text/plain
curl -I https://coltlang.pages.dev/install.ps1
curl -I https://coltlang.pages.dev/install.cmd
curl -I https://coltlang.pages.dev/install.sh
Step 4

Update DNS & Cutover Traffic

  1. In your DNS registrar (e.g. Cloudflare DNS, Route53, Namecheap), update the CNAME record for coltlang.dev to point to coltlang.pages.dev.
  2. Cloudflare automatically issues and provisions the SSL/TLS certificate.
  3. Leave the Vercel deployment active for at least 48 hours to serve any lingering DNS caches before deleting the old project.

Changing to a New Canonical Domain

If ColtLang migrates to a different domain name in the future:

1. Central Configuration Update

Update PUBLIC_SITE_URL in your deployment environment variables or website/site.config.js:

// website/site.config.js
const PUBLIC_SITE_URL = process.env.PUBLIC_SITE_URL || 'https://newdomain.org';

2. Preserving Legacy Redirects (301 Permanent)

Maintain ownership of the old domain and configure HTTP 301 redirects to preserve exact paths. In vercel.json or Cloudflare Page Rules: 

"redirects": [
  { "source": "/install.ps1", "destination": "https://newdomain.org/install.ps1", "permanent": true },
  { "source": "/install.cmd", "destination": "https://newdomain.org/install.cmd", "permanent": true },
  { "source": "/install.sh", "destination": "https://newdomain.org/install.sh", "permanent": true },
  { "source": "/(.*)", "destination": "https://newdomain.org/$1", "permanent": true }
]
Redirect Handling in CLI Installers
Notice that the official installation instructions use curl -fsSL and PowerShell's Invoke-RestMethod, both of which automatically follow HTTP 301/302 redirects seamlessly.

Installer Endpoint Health Checklist

Always verify the following criteria after any deployment or DNS change:

  • MIME Type: Endpoints return Content-Type: text/plain; charset=utf-8 so terminals do not receive HTML error pages.
  • CORS: Access-Control-Allow-Origin: * header is present.
  • No Shell Execution on 404: Errors return non-zero HTTP status codes rather than 200 OK fallback pages.
  • Authoritative Sync: Installer bodies in dist/ strictly match the canonical versions in scripts/.

Instant Rollback Procedure

If any verification check fails during a migration:

  1. Revert DNS CNAME records back to the prior hosting provider target.
  2. Both Vercel and Cloudflare Pages maintain instant deployment rollback in their respective dashboards with a single click.
  3. Test endpoints with curl -I to ensure zero broken installation requests.
